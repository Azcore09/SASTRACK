# SAS-TRACK — JavaFX sample (in-memory data, no Oracle yet)

This is a working sample of the desktop app using **in-memory sample data**
(`DataStore.java`) instead of Oracle, so you can see the whole UI and
navigation flow before wiring up the real database.

## How to run

1. Copy this project structure into your existing Gradle project, replacing
   your `HelloApplication` / `HelloController` / `Launcher` files with the
   ones here (`MainApp.java` replaces `HelloApplication.java` — same role,
   renamed to fit the app).
2. Make sure `build.gradle` includes the `org.openjfx.javafxplugin` plugin
   (already set up in this sample's `build.gradle`).
3. Run with `./gradlew run`, or run `Launcher.java` directly from your IDE.
4. Sign in with a demo account:
   - Admin (SAS Head): `j.delacruz` / `admin123`
   - Staff (SAS Staff): `m.fernandez` / `staff123`

## Package the desktop app

To produce a native app image with `jpackage`, run:

```bash
./gradlew jpackageAppImage
```

The packaged app is created under `build/jpackage/` and can be launched directly without needing Gradle or a Java IDE.

## What's implemented

- **Login** — checks credentials against `DataStore.USERS` and carries the
  role (`isAdmin()`) in `Session` for the rest of the app to check. Deleting
  a record currently requires an admin account (try it while logged in as
  staff to see the block).
- **Collapsible sidebar** — the `⟨ / ⟩` button on the sidebar shrinks it to
  icon-only width.
- **Lost & Found nav group** — All items / Unclaimed / Claimed / Log found
  item, each swaps the table filter or opens the log-item dialog directly.
- **Guidance Violations nav group** — same pattern, filtered by Minor /
  Major / Serious, plus Add violation.
- **Dashboard** — four clickable stat cards (Total records, Lost & Found,
  Active violations, Resolved cases) that jump straight to the filtered
  table behind each number. The offense-type chart toggles between
  "by month" (within the selected school year) and "by year" (across all
  school years).
- **School year archive** — every record carries a `schoolYear` field.
  Dashboard and both table views have a School Year filter so you can pull
  up 2025-2026 records without touching 2026-2027 data.
- **Toggleable search** — the top bar's dropdown switches between
  searching Violations or Lost & Found, and opens a dedicated results view.

## Swapping in Oracle later

Nothing in the controllers talks to `DataStore` fields directly by index —
they use `DataStore.VIOLATIONS` / `DataStore.ITEMS` as `ObservableList`s.
When you're ready to connect Oracle:

1. Add `ojdbc11` + `spring-boot-starter-data-jpa` (or plain JDBC/DAO classes
   if you'd rather skip Spring).
2. Turn `Violation` and `LostItem` into `@Entity` classes (or map them from
   `ResultSet` rows in a DAO).
3. Replace `DataStore.VIOLATIONS` / `DataStore.ITEMS` with a repository call
   that loads into the same `ObservableList` shape — the controllers and
   FXML don't need to change.
4. Move `DataStore.nextViolationId()` / `nextItemId()` to Oracle sequences
   or `GENERATED BY DEFAULT AS IDENTITY` columns.

I can help wire that up whenever you're ready to move off the in-memory data.
